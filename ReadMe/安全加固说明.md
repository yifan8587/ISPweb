# 安全加固说明

门户部署后，页面、接口和 VNC 都只经过指定域名的 HTTPS。下面是安装脚本实际启用的控制，以及每项负责的事情。

## 1. URL 编码混淆

生产包里的接口不再使用明文 `/api/...` 或 `/ws/...`。

浏览器先把真实路径、查询参数和请求方法放进一段 JSON，用部署密钥派生的掩码做逐字节混淆，再编码成 Base64URL。页面实际请求：

- 普通接口：`/_g/<混淆串>`
- VNC WebSocket：`/_gws/<混淆串>`

Nginx 上的明文位置会直接断开：

- `/api`
- `/ws`

因此扫描器按常见接口路径访问时，到不了 ISPmanager。访问日志也只记录 `/_g/` 或 `/_gws/`，不记录混淆串全文和查询参数。VNC 票据留在混淆串内部，由本机网关还原后再发给后端。

开发时的 `npm run dev` 仍使用明文代理，方便调试。给服务器的包必须由 `./deploy/pack.sh` 生成。

## 2. 参数杂凑

混淆串外面只允许三个参数：

- `_t`：Unix 秒级时间戳
- `_n`：32 位十六进制随机串
- `_h`：HMAC-SHA256

杂凑覆盖请求方法、混淆串、请求体的 SHA-256、时间戳和随机串。查询参数在进入混淆串之前按名称排序，并拒绝同名参数，避免参数污染。请求体参与杂凑后，网关按原始字节转发给 API。

网关使用 `hmac.compare_digest` 比较签名。比较失败、时间超出窗口、随机串重放、参数重复或编码异常时，严格模式对外只返回空的 404，具体原因写在 `ispweb-urlguard` 日志里。

默认时间窗口是 120 秒。服务器需要保持时钟同步，Ubuntu 22.04 / 24.04 的 `systemd-timesyncd` 即可。

## 3. 严格模式

`/etc/ispweb/ispweb.env` 中的 `URL_GUARD_STRICT=1` 是生产默认值。严格模式同时在 Nginx 和本机网关生效：

- 只接受 `GET`、`HEAD`、`POST`、`PUT`、`PATCH`、`DELETE`、`OPTIONS`
- 还原后的路径只能是门户会用到的接口：登录、`/api/auth/me`、`/api/portal/`、支付交易查询，以及 VNC 的 `/ws/resource/vnc/`。管理接口到不了上游
- 拒绝 `..`、反斜杠、空字节、双重编码、编码后的斜杠和目录穿越
- 拒绝外层查询里出现签名三件套以外的参数
- 拒绝重复头部、分块传输和超长正文。接口正文上限 2 MB
- `Origin` 或 `Referer` 如果出现，必须是 `https://配置的域名`
- 登录 `/api/auth/token` 和注册 `/api/portal/register` 每个来源地址每分钟最多 20 次，超出返回 429
- 网关只接受来自本机 Nginx 的连接

把 `URL_GUARD_STRICT` 改成 `0` 后，失败响应会带上原因码，便于排障。签名和路径混淆仍然生效。排障结束后改回 `1` 并重启网关。

## 4. 只允许域名，不允许 IP

Nginx 有两组默认站点，分别监听 80 和 443。Host 是 IP、空 Host，或不是配置域名时，连接以 444 直接断开，不会跳转到真实域名，也不会返回页面。

安装时加 `--allow-ip` 会额外放行这台服务器的一个公网 IP：nginx 把门户站点设为 443 默认站点（IP 访问不带 SNI），Host 只接受域名和该 IP；网关同样只接受这两个 Host，且 Origin、Referer 必须与 Host 一致，转发给管理端的 Origin 仍写成门户域名。其他 IP 与 Host 照旧断开。

443 的未知 SNI 使用系统自签占位证书完成握手后立即断开。正式证书只发给配置的域名。

站点内部还会再检查一次 Host。因此即使 TLS 的 SNI 是正确域名，请求头里的 Host 仍必须是该域名。

## 5. TLS 与 80 到 443

正式站点只在 443 提供内容，协议是 TLS 1.2 和 TLS 1.3，密码套件为 ECDHE 加 AES-GCM 或 ChaCha20。会话票据关闭。

80 端口保留 `/.well-known/acme-challenge/` 给证书续期，其余请求返回：

```text
301 https://配置的域名<原始路径>
```

certbot 和自备证书会加上 HSTS，有效期 180 天。自签证书不加 HSTS，避免浏览器把实验环境的证书错误记住。提供了证书链时开启 OCSP Stapling。

## 6. 其余加固

这些项随安装写入 Nginx、systemd 或文件权限：

- `server_tokens off`，错误页不显示 Nginx 版本
- 安全响应头：`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy`、`Cross-Origin-Opener-Policy`、`Cross-Origin-Resource-Policy`，以及限制摄像头、麦克风、地理位置等的 Permissions-Policy
- 内容安全策略只允许本站脚本、本站连接和必要的内联样式。接口和 VNC 都走同一域名
- 页面入口不缓存，带哈希的 `/assets/` 长期缓存
- 接口与 WebSocket 每秒 10 个请求、突发 20；页面每秒 30 个请求。每个地址还有并发连接限制
- 接口响应关闭 gzip，降低压缩侧信道对动态内容的影响
- 屏蔽常见探测路径，例如 `.git`、`.env`、`wp-admin`、`phpmyadmin`
- 网关以系统用户 `ispweb` 运行，不能登录，服务启用 `NoNewPrivileges`、`PrivateTmp`、`ProtectSystem=strict`
- 程序目录中的部署文件属主是 `root:ispweb`，权限 `750/640`。网站静态文件另给 `www-data` 只读
- `/etc/ispweb/ispweb.env` 权限 `600`
- 可选 fail2ban 对持续产生 444 的来源封禁 1 小时。见安装说明中的 `--with-fail2ban`

## 7. 密钥和登录态

混淆密钥会进入前端包，因为浏览器必须用它计算杂凑。它的作用是让没有这套页面逻辑的请求无法直接调用接口，并让参数在到达网关前不能被悄悄改掉。

用户是否已登录，仍由 ISPmanager 的访问令牌判断。网关不取代后端认证。后端应继续校验令牌、权限和业务参数。

分机部署时，网关还会带上 `PORTAL_API_SECRET`。这把密钥只放在两台服务器的环境文件里，不进前端包。管理端只接受门户服务器出口地址访问门户 API 端口，并且只处理上面列出的路径。

更换密钥的唯一方法是重新执行 `./deploy/pack.sh` 并整包更新。更新说明里的回滚也要连同那一版的密钥一起退回。

## 8. 建议在系统上另外确认的事项

安装脚本不会改主机防火墙的总开关，也不会改 SSH。上线前建议确认：

- 域名解析指向这台服务器，证书与域名一致
- ISPmanager 只监听本机或受控内网，不把管理端口暴露到公网
- 系统已启用时钟同步
- 80 和 443 以外的业务端口按实际需要关闭
- 正式环境使用 certbot 或企业证书，而不是自签证书
