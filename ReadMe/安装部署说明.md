# 安装部署说明

目标系统是全新安装的 Ubuntu 22.04 或 24.04。脚本会安装 Nginx、准备证书、写入 API 上游，并启动只监听本机的访问网关。只开放 HTTPS，HTTP 一律跳转到 HTTPS。

## 与 ISPmanager 的关系

门户是纯前端，所有接口都由本机网关转发到 ISPmanager 的**门户 API 端口**。安装前需要先装好管理端，并从管理端服务器的 `/root/ispmanager-credentials.txt` 取下面两项：

| 管理端凭据文件里的字段 | 门户安装参数 |
|---|---|
| `portal_api_upstream`，例如 `https://manager.example.com:8443` | `--api` |
| `portal_api_secret` | `--portal-secret` |

管理端安装时填写的门户服务器出口 IP（`PORTAL_API_ALLOW_CIDRS`）必须包含这台门户服务器的出口公网 IP，否则门户 API 端口会直接拒绝连接。

## 安装前

- 域名已经解析，或即将解析到这台服务器。`--domain` 必须是域名；需要再用公网 IP 访问时，另加 `--allow-ip`，见下文。
- ISPmanager 的门户 API 已经在安装参数里的地址上监听。分机部署时写成 `https://管理端域名:8443`，并带上与管理端相同的 `--portal-secret`。同一台机器调试时仍可使用 `http://127.0.0.1:8000`，这时可以不填密钥。
- 使用 80 和 443 端口。80 只负责证书校验和跳转到 443。
- 使用 certbot 时，80 端口需要能从公网访问到这台机器。

## 上传并解压

```bash
scp deploy/output/ispweb-1.0.3-时间戳.tar.gz root@服务器:/root/
ssh root@服务器
cd /root
sha256sum -c ispweb-1.0.3-时间戳.tar.gz.sha256
tar -xzf ispweb-1.0.3-时间戳.tar.gz
cd ispweb-1.0.3-时间戳
```

## 安装

正式证书：

```bash
sudo ./deploy/install.sh \
  --domain portal.example.com \
  --api https://manager.example.com:8443 \
  --portal-secret '与 ISPmanager 的 PORTAL_API_SECRET 相同' \
  --ssl certbot \
  --email admin@example.com
```

管理端证书是自签时，安装会自动钉住当前证书。也可以自行提供 `--ca-file /path/fullchain.pem`。只在实验室跳过校验时才使用 `--tls-insecure`。API 写成 IP 时，网关会改用证书里的域名作为主机名。

实验室自签证书：

```bash
sudo ./deploy/install.sh \
  --domain portal.example.com \
  --api http://127.0.0.1:8000 \
  --ssl self-signed
```

已有证书文件：

```bash
sudo ./deploy/install.sh \
  --domain portal.example.com \
  --api http://127.0.0.1:8000 \
  --ssl provided \
  --ssl-cert /root/certs/fullchain.pem \
  --ssl-key /root/certs/privkey.pem \
  --ssl-chain /root/certs/chain.pem
```

同时允许用这台服务器的公网 IP 访问（`https://公网IP/`）：

```bash
sudo ./deploy/install.sh \
  --domain portal.example.com \
  --api https://manager.example.com:8443 \
  --portal-secret '与 ISPmanager 的 PORTAL_API_SECRET 相同' \
  --ssl certbot --email admin@example.com \
  --allow-ip
```

- 脚本先看网卡上的公网地址，NAT 后再向外部服务探测出口 IP。探测不到或不准时用 `--public-ip 1.2.3.4` 指定，指定了 `--public-ip` 就等于开启 `--allow-ip`。
- 用 IP 访问时浏览器不会发送域名（SNI），nginx 会把门户站点设为 443 的默认站点，出示的仍是域名证书，所以浏览器会提示证书与地址不符，需要手工继续。`--ssl self-signed` 时自签证书会同时写入该 IP。
- `http://公网IP/` 跳转到 `https://公网IP/`。其他 IP 或 Host 仍然直接断开。
- 在线支付完成后跳回的地址固定是门户域名。
- 已安装的门户可在更新时开启或关闭：`sudo ./deploy/update.sh 包.tar.gz --public-ip 1.2.3.4`，或 `--no-ip-access`。

也可以把参数写进文件后执行 `sudo ./deploy/install.sh --config /root/ispweb-install.env`。样例在 `deploy/config.env.example`。命令行参数优先于配置文件。

在源码目录里直接安装时，先执行 `./deploy/pack.sh`，再执行 `sudo ./deploy/install.sh ...`。只要项目根目录还有 `vite.config.js`，安装脚本会把最终 API 地址写回该文件。

## 安装脚本做了什么

1. 检查系统是 Ubuntu 22.04 或 24.04。其他系统实验时可加 `--force-os`。
2. 安装 `nginx`、`python3`、`openssl`、`ca-certificates`、`ssl-cert`、`curl`。certbot 模式再安装 `certbot`。
3. 把前端放到 `/opt/ispweb/releases/<时间>/`，并用 `/opt/ispweb/current` 指向它。
4. 把 API 地址、域名、证书路径和混淆密钥写入 `/etc/ispweb/ispweb.env`，文件权限 `600`。
5. 按证书方式签发或安装证书。certbot 先只开放 `/.well-known/acme-challenge/`，签发成功后再切换正式配置。
6. 生成 `/etc/nginx/sites-available/ispweb.conf`：
   - 指定域名的 80 端口跳转到 `https://域名`
   - 443 提供页面和加密访问
   - 用 IP 或其他 Host 访问时直接断开；开启 `--allow-ip` 后放行这台服务器的公网 IP
7. 启动 `ispweb-urlguard.service`。网关只监听 `127.0.0.1:8765`，校验通过后再连接 `API_UPSTREAM`。

安装结束会打印 `https://域名/`、API 上游和密钥指纹。请核对指纹与打包机输出一致。

证书按使用场景选择：

- `certbot`：域名已经指向这台服务器，需要浏览器信任的正式证书。
- `provided`：使用手里已有的全链证书和私钥。
- `self-signed`：只在实验室验证。浏览器会提示不受信任，这种证书不写 HSTS。

自签证书按域名保存在 `/etc/ispweb/ssl/`。同一域名重复安装会沿用已有自签证书。

## 防火墙

脚本发现 ufw 已经启用时，会放行 TCP 80 和 TCP 443。ufw 未启用时不会主动打开，避免把现有 SSH 策略改掉。需要手工放行时：

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```

## 安装后的检查

```bash
systemctl status nginx ispweb-urlguard
sudo nginx -t
curl -fsS http://127.0.0.1:8765/healthz
curl -I https://portal.example.com/
```

未开启 IP 访问时，用服务器 IP 访问 80 或 443，连接应被直接断开。开启后 `curl -kI https://公网IP/` 应返回 200。用域名访问时，`http://域名` 应跳到 `https://域名`。

页面能打开但接口失败时，先确认 ISPmanager 正在监听 `/etc/ispweb/ispweb.env` 里的 `API_UPSTREAM`。

## 可选的 fail2ban

对持续探测并收到 444 的地址做封禁：

```bash
sudo ./deploy/install.sh --domain portal.example.com --ssl certbot --email admin@example.com --with-fail2ban
```

默认不安装 fail2ban。规则只看本站访问日志里的 444，不改 SSH 策略。

## 卸载

```bash
sudo ./deploy/uninstall.sh
```

这会停止网关、删除 Nginx 站点和 `/opt/ispweb`。`/etc/ispweb` 里的环境文件和自签证书仍保留。连同这些一起删除：

```bash
sudo ./deploy/uninstall.sh --purge
```

Let's Encrypt 证书仍留在 `/etc/letsencrypt`，需要时用 certbot 自己的命令删除。
