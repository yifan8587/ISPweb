# 打包说明

打包在构建机完成。构建机需要：

- Node.js 18 或更高版本
- npm
- Python 3
- OpenSSL

服务器不需要安装 Node.js。

## 命令

在项目根目录执行：

```bash
./deploy/pack.sh --api http://127.0.0.1:8000
```

省略 `--api` 时，脚本读取 `vite.config.js` 里现有的默认地址。

脚本会做四件事：

1. 把 API 地址写入 `vite.config.js` 中 `DEPLOY_API_PROXY_TARGET` 标记之间的默认值。
2. 生成本次构建专用的混淆密钥，写入被 git 忽略的 `.env.deploy.local`。
3. 以 `deploy` 模式构建前端。这个模式才会把 URL 混淆和参数杂凑编进页面。
4. 生成安装包 `deploy/output/ispweb-<版本>-<时间>.tar.gz` 和同名 `.sha256`。

终端会打印密钥指纹。指纹可以用来核对服务器，完整密钥只放在安装包里，不要单独抄到聊天或工单。

## 安装包里有什么

- `dist/`：已混淆的前端
- `deploy/`：安装、更新、卸载脚本，Nginx 模板和本机网关
- `deploy/package.env`：API 地址、版本，以及与这次前端绑定的 `URL_GUARD_SECRET`

安装包权限是 `600`。传到服务器时使用 scp 或同等的受限通道，放到 root 可读写的目录。

## 开发构建和部署构建

日常开发继续使用：

```bash
npm run dev
```

开发服务器仍按 `vite.config.js` 把明文 `/api`、`/ws` 代理到后端，方便本机调试。

`npm run build` 是普通生产构建，不启用 URL 混淆。要给服务器使用的包，请走 `./deploy/pack.sh`。

## 更换 API 地址

后端仍在本机、只是端口或地址变了时，可以在安装时用 `--api` 覆盖，不必为了改上游重新打包。浏览器始终访问门户自己的域名，由服务器网关去连接 API。

重新打包会生成新的混淆密钥。新包必须整包部署，不能只替换其中几个 js 文件。
